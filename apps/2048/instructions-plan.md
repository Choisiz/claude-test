# plan 서브에이전트 지침: 2048 게임

## 역할
2048 웹앱의 **계획서만** 작성한다. 코드는 구현하지 않는다.

## 수정 허용 범위
- 생성/수정 가능: `/Users/cky/dev/my-blog/apps/2048/spec.md` (이 파일 하나뿐)
- 그 외 모든 파일은 읽기만 한다. 특히 블로그 파일(`index.html`, `post.html`, `css/`, `js/`, `posts/`, `CLAUDE.md`, `.claude/`)은 수정 금지.

## 프로젝트 규칙 (CLAUDE.md 발췌)
- html, js, css만 사용한다. 프레임워크 금지.
- 웹앱은 `/apps/2048/` 폴더 안에서 자체 완결된다.
- 외부 라이브러리는 최소화한다. 가능하면 사용하지 않는다. CDN은 허용.
- 모바일에서도 사용할 수 있어야 한다.

## 사용자 요구사항
- 방향키로 숫자 타일을 밀어서 같은 숫자끼리 합치는 퍼즐 게임 (2048)
- 점수판 포함

## spec.md에 반드시 포함할 내용
1. **개요**: 만들 앱 한 문단 요약
2. **기능 목록**: 필수 기능과 선택 기능을 구분
   - 필수: 4x4 보드, 방향키 이동·병합, 새 타일 생성(2 또는 4), 현재 점수와 최고 점수 표시, 새 게임 버튼, 게임 오버 판정, 2048 달성 표시
   - 모바일: 터치 스와이프 조작, 작은 화면 대응
   - 최고 점수 저장 방식 (localStorage, 접근 실패 시 동작)
3. **게임 규칙 정의**: 한 줄 이동·병합 알고리즘(한 번의 이동에서 한 타일은 한 번만 합쳐짐), 점수 계산, 이동이 없으면 새 타일을 만들지 않는 조건, 새 타일 확률
4. **파일 구조**: `/apps/2048/` 안의 파일 목록과 각 파일의 책임 (예: `index.html`, `style.css`, `game.js` 로직, `ui.js` 렌더·입력)
5. **UI 설계**: 레이아웃, 점수판 배치, 타일 색상 규칙, 라이트/다크 모드 대응, 이동·병합 애니메이션 방침
6. **입력 처리**: 방향키, 스와이프(임계값), 페이지 스크롤과의 충돌 방지
7. **접근성**: 키보드 조작, aria 속성(점수 변화 안내 등)
8. **엣지 케이스**: 연속 빠른 입력, 보드가 가득 찼지만 합칠 수 있는 경우, 2048 이후 계속 플레이
9. **검증 체크리스트**: review 단계에서 확인할 항목 목록
10. **열린 질문**: 사용자에게 확인이 필요한 결정 사항 (없으면 "없음")

## 작성 방식
- 한국어로, 구현자가 그대로 따를 수 있을 만큼 구체적으로 쓴다.
- 과한 기능은 넣지 않는다. 요구사항 범위를 지킨다.
