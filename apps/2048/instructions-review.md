# review 서브에이전트 지침: 2048 게임

## 역할
build 서브에이전트가 만든 2048 앱을 **독립적으로 검증**한다. 구현자의 보고를 믿지 말고 직접 확인한다. 결과를 `review.md`에 기록하고, 문제가 있으면 수정한다.

## 수정 허용 범위
- 생성 가능: `/Users/cky/dev/my-blog/apps/2048/review.md`
- 문제 발견 시 수정 가능: `apps/2048/index.html`, `style.css`, `game.js`, `ui.js` (이 4개만, 최소한으로 수정하고 무엇을 왜 고쳤는지 review.md에 기록)
- 수정 금지: `spec.md`, `instructions-*.md`, 블로그 파일(`index.html`(루트), `post.html`, `css/`, `js/`, `posts/`, `CLAUDE.md`, `.claude/`)
- git 명령(커밋 포함)은 실행하지 않는다.

## 검증 환경
- 로컬 서버가 이미 `http://localhost:8000` 에서 실행 중이다. 앱 주소: `http://localhost:8000/apps/2048/`
- 서버를 새로 띄우거나 종료하지 않는다.
- 임시 스크립트는 스크래치패드(`/private/tmp/claude-501/-Users-cky-dev-my-blog/16083f15-a54b-4bbb-ae86-c885f2ef8079/scratchpad`)에 두고 프로젝트에는 남기지 않는다.

## 검증 항목
1. **계획 대비 구현**: `spec.md` 3절(규칙), 4절(파일 구조), 10절(확정 결정)과 코드가 일치하는지 읽어서 확인한다.
2. **로직 단위 검증 (Node)**: `game.js`를 직접 import해 `slideLine` 예시 5개, 4방향 이동 대칭성, 병합 한 번 규칙, 이동 없는 입력 무시, 새 타일 확률 분포, 게임 오버 판정(가득 찼지만 합칠 수 있는 경우 포함), 2048 달성 및 계속하기를 확인한다.
3. **브라우저 동작**: 브라우저 도구를 사용할 수 있으면 실제로 열어서 확인한다.
   - 방향키/WASD 이동, 점수 증가, 최고 점수 유지(새로고침 후), 새 게임, 게임 오버/2048 오버레이
   - 콘솔 에러 없음
   - 375px 폭에서 가로 스크롤 없음, 라이트/다크 모두 확인
   - 브라우저 도구를 쓸 수 없으면 쓸 수 없다고 review.md에 명시하고, 그 항목은 "미검증"으로 표시한다(통과로 쓰지 않는다).
4. **코드 점검**: spec.md 9절 "규칙 준수" 항목(프레임워크/CDN 없음, 색상 하드코딩 없음, 인라인 핸들러 없음, `var` 미사용, `game.js`에 DOM 접근 없음), 접근성 속성, 보안(innerHTML 사용 여부 등).
5. **spec.md 9절 체크리스트** 전 항목: 통과 / 실패 / 미검증으로 표시.

## review.md 형식
1. 요약 (통과 여부 한 줄)
2. 체크리스트 결과 표 (항목, 결과, 근거)
3. 발견한 문제와 수정 내역 (파일, 줄, 원인, 수정 내용). 없으면 "없음"
4. 미검증 항목과 이유
5. 남은 위험 또는 권고

## 원칙
- 직접 확인하지 않은 것을 통과로 쓰지 않는다.
- 수정 후에는 해당 항목을 다시 검증한다.
- 막히면 막힌 이유를 review.md와 보고에 명시한다.

## 완료 보고
통과/실패 요약, 고친 문제, 미검증 항목을 5줄 이내로 보고한다.
