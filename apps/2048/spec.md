# 2048 게임 계획서 (spec)

## 1. 개요

`/apps/2048/` 안에서 자체 완결되는 2048 웹앱이다. 4x4 보드에서 방향키(모바일은 스와이프)로 모든 타일을 한 방향으로 밀고, 같은 숫자의 타일이 맞닿으면 합쳐 점수를 얻는다. 순수 HTML/CSS/JS(ES Modules)만 사용하며 프레임워크, 빌드 도구, 외부 라이브러리, CDN을 쓰지 않는다. 현재 점수와 최고 점수를 보여 주는 점수판, 새 게임 버튼, 게임 오버 및 2048 달성 표시를 포함한다. 색상 톤은 블로그(`css/base.css`)의 토큰 구성(배경/표면/텍스트/보더/accent)과 시스템 폰트 스택을 참고하되, 앱 폴더 밖 파일은 import하지 않고 자체 CSS 변수를 정의한다.

## 2. 기능 목록

### 필수
- 4x4 보드, 시작 시 타일 2개 생성
- 방향키(←↑→↓) 이동 및 병합
- 이동 후 새 타일 1개 생성 (2 또는 4)
- 현재 점수, 최고 점수 표시
- 새 게임 버튼
- 게임 오버 판정과 오버레이 표시
- 2048 타일 달성 표시 (오버레이, "계속하기"/"새 게임" 선택)

### 모바일
- 터치 스와이프 조작
- 작은 화면 대응: 360px 폭에서 가로 스크롤 없음, 보드는 `min(92vw, 28rem)` 정사각형

### 최고 점수 저장
- `localStorage` 키 `2048:best` 에 정수 문자열로 저장한다.
- 점수가 최고 점수를 넘는 즉시 갱신·저장한다.
- 읽기/쓰기는 모두 `try/catch`로 감싼다. 실패(비공개 모드, 차단, 값이 숫자가 아님) 시 최고 점수는 메모리에서만 유지하고 0에서 시작하며, 오류 UI는 띄우지 않는다.

### 선택 (이번 범위에서 제외 권장)
- 실행 취소(undo), 진행 중 게임 저장·복원, 사운드, 4x4 외 보드 크기. 요구사항 범위를 지키기 위해 구현하지 않는다.

## 3. 게임 규칙 정의

### 한 줄 이동·병합 알고리즘
모든 방향 이동은 "한 줄을 왼쪽으로 민다"는 단일 함수로 처리한다. 오른쪽/위/아래는 줄을 뽑을 때 순서를 뒤집거나 전치해서 같은 함수를 재사용한다.

`slideLine(line: number[4]) -> { line: number[4], gained: number, moved: boolean }`
1. 0을 제거해 숫자만 앞으로 모은다. 예: `[2,0,2,4]` -> `[2,2,4]`
2. 앞에서부터 순회하며, 현재 값과 다음 값이 같으면 합쳐 `값*2`로 하나만 출력하고 두 칸을 소비한다. 합쳐진 결과는 같은 이동에서 다시 합쳐지지 않는다(한 타일은 한 번의 이동에서 한 번만 병합). 같지 않으면 현재 값을 그대로 출력하고 한 칸 소비한다.
3. 뒤를 0으로 채워 길이 4로 만든다.
4. `gained`는 이번 줄에서 생긴 병합 타일 값의 합, `moved`는 결과가 입력과 다른지 여부.

검증 예시
- `[2,2,2,2]` -> `[4,4,0,0]`, gained 8
- `[2,2,2,0]` -> `[4,2,0,0]`, gained 4
- `[4,2,2,0]` -> `[4,4,0,0]`, gained 4 (새로 생긴 4가 앞의 4와 다시 합쳐지지 않음)
- `[2,0,0,2]` -> `[4,0,0,0]`, gained 4
- `[2,4,8,16]` -> 변화 없음, moved false

### 점수 계산
- 병합으로 생긴 타일의 값을 점수에 더한다 (2+2 -> +4, 1024+1024 -> +2048).
- 이동만 하고 병합이 없으면 점수 변화 없음.
- 새 게임 시 현재 점수 0, 최고 점수는 유지.

### 새 타일 생성
- 이동 4방향 합산 결과 `moved === true`일 때만 새 타일을 만든다. 보드가 하나도 바뀌지 않는 입력은 무시하며 새 타일도, 점수 변화도 없다.
- 빈 칸 중 균등 무작위로 한 칸을 고른다.
- 값은 90% 확률로 2, 10% 확률로 4.
- 시작 시에도 같은 규칙으로 2개를 생성한다.

### 종료 판정
- 게임 오버: 빈 칸이 없고, 가로·세로로 인접한 같은 값 쌍이 없을 때. 이동 후 새 타일을 생성한 직후에 검사한다.
- 2048 달성: 병합 결과로 2048 타일이 처음 생길 때 한 번만 `won` 상태로 전환한다.

## 4. 파일 구조

`/apps/2048/` 안에서만 완결된다. 모든 경로는 상대 경로를 사용한다.

```
apps/2048/
├── index.html   # 마크업, 테마 FOUC 방지 인라인 스크립트, <script type="module" src="ui.js">
├── style.css    # CSS 변수(라이트/다크), 레이아웃, 타일 색상, 애니메이션
├── game.js      # 순수 로직 (DOM 접근 금지)
├── ui.js        # 렌더링, 입력(키보드/터치), 최고 점수 저장, 오버레이, aria-live
├── spec.md      # 이 문서
└── instructions-plan.md
```

### game.js 책임 (export)
- `createGame(random = Math.random)`: 상태 `{ grid, score, won, over, keepPlaying }` 생성, 시작 타일 2개 배치. 난수 함수를 주입받아 테스트 가능하게 한다.
- `slideLine(line)`: 위 알고리즘.
- `move(state, direction)`: `'left'|'right'|'up'|'down'`. 새 상태와 `{ moved, gained, tiles }`(애니메이션용 이동·병합 정보)를 반환. 새 타일 생성 포함. 입력 상태를 변경하지 않는 불변 방식을 권장한다.
- `canMove(grid)`: 빈 칸 또는 인접 동일 값 존재 여부.
- 타일 식별: 애니메이션을 위해 각 타일은 고유 `id`를 가진다(병합 시 새 id, 이동만 하면 기존 id 유지). 구현자는 `grid`를 `{id, value}|null` 2차원 배열로 하거나, 값 배열과 별도의 이동 정보를 반환하는 방식 중 단순한 쪽을 택한다.

### ui.js 책임
- 상태 보관, 렌더링, 키보드·터치 이벤트, localStorage 접근, 오버레이 및 버튼 이벤트 연결, 점수 안내용 live region 갱신.

## 5. UI 설계

### 레이아웃 (위에서 아래로, 중앙 정렬, 최대 폭 `28rem`)
1. 헤더 행: 좌측 제목 "2048", 우측 점수 박스 2개(현재 점수 / 최고 점수)
2. 설명 한 줄 + "새 게임" 버튼: "방향키 또는 스와이프로 같은 숫자를 합쳐 2048을 만드세요."
3. 보드: 정사각형, 4x4 셀, 간격 `--gap`, 보드 안 패딩 동일
4. 하단: 조작 안내 보조 텍스트(선택)

점수 박스 라벨은 "점수", "최고". 점수 증가 시 `+N`을 점수 박스 위에 짧게 띄우는 효과는 선택(애니메이션 감소 설정 시 생략).

### 보드 구현 방침
- 배경 셀 16개(고정)와, 그 위에 절대 배치되는 타일 레이어를 분리한다.
- 타일 위치는 `transform: translate(calc(var(--x) * (100% + var(--gap))), calc(var(--y) * (100% + var(--gap))))` 형태로 CSS 변수에서 계산한다. 셀 크기는 `calc((100% - 3 * var(--gap)) / 4)`.
- 글자 크기는 보드 폭 기준으로 가변(`container-type: inline-size` + `cqw` 단위 사용 가능, 미지원 대비 clamp 대체). 4자리 숫자는 더 작게 한다.

### 색상 규칙
- 모든 색은 `style.css` 상단의 CSS 변수로 정의하고 이후에는 변수만 참조한다.
- 라이트/다크: 앱은 시스템 설정(`prefers-color-scheme`)을 따르며, 블로그가 설정한 `localStorage`의 `theme` 키(`light|dark`)가 있으면 읽어 `<html data-theme>`에 반영하는 FOUC 방지 인라인 스크립트를 `<head>`에 둔다. 앱 내 별도 토글 버튼은 만들지 않는다(범위 최소화). `<meta name="color-scheme" content="light dark">` 포함.
- 블로그 토큰과 같은 이름(`--bg`, `--surface`, `--text`, `--text-muted`, `--border`, `--accent`)을 쓰고 값도 유사하게 맞춰 톤을 통일한다.
- 타일 값별 색상: 하나의 hue(블로그 accent 계열의 파랑)를 기준으로 값이 커질수록 채도·명도 대비가 강해지는 단계형 팔레트를 사용한다. 값 2~2048까지 11단계를 `--tile-2` ... `--tile-2048` 변수로 정의하고, 4096 이상은 `--tile-super` 하나로 처리한다. 라이트/다크 각각 값을 정의한다.
- 각 타일 배경 대비 글자색(`--tile-N-text`)을 함께 정의해 숫자 텍스트 대비 WCAG AA 4.5:1 이상을 유지한다. 색만으로 구분하지 않도록 숫자는 항상 표기한다.
- 빈 셀은 `--surface` 계열, 보드 배경은 `--border` 계열.

### 애니메이션 방침
- 이동: `transform` 전환 120ms ease-out.
- 신규 타일: scale 0 -> 1 (120ms, 이동 후 약간 지연).
- 병합: 합쳐진 타일이 scale 1 -> 1.12 -> 1 (120ms) 팝.
- `transform`/`opacity`만 애니메이션한다.
- `@media (prefers-reduced-motion: reduce)`에서는 모든 전환·애니메이션을 제거하고 즉시 반영한다.
- 애니메이션 중에도 상태는 즉시 갱신되며, 입력을 막지 않는다(8절 참조).

### 오버레이
- 게임 오버: 보드 위 반투명 오버레이, 문구 "게임 오버", 최종 점수, "다시 시작" 버튼.
- 2048 달성: 문구 "2048 달성!", 버튼 "계속하기" / "새 게임".
- 오버레이는 보드와 같은 크기로 덮고, 표시되면 첫 버튼으로 포커스를 이동한다.

## 6. 입력 처리

### 키보드
- 방향키 ←↑→↓ 가 기본. 보조로 WASD 도 허용한다(선택, 구현 비용 낮음).
- `keydown`에서 처리하고, 처리한 키에 대해 `preventDefault()`를 호출해 방향키로 페이지가 스크롤되지 않게 한다.
- `event.repeat`(키 길게 누름)은 무시하지 않는다. 다만 8절의 동기 처리 덕에 문제 없다. 단, 수정키(Ctrl/Alt/Meta)가 눌린 경우는 처리하지 않는다.
- 포커스가 `button`, `input` 등에 있어도 방향키는 게임에 적용한다. 스페이스/엔터는 기본 동작(버튼 클릭)을 유지한다.
- 오버레이가 표시 중이면(게임 오버, 2048 달성 선택 대기) 이동 입력을 무시한다.

### 터치 스와이프
- 보드 요소에 `touchstart` / `touchend`(또는 Pointer Events)로 시작·종료 좌표를 기록한다.
- 임계값: 주 축 이동 거리가 `30px` 이상이어야 스와이프로 인정. 축 판정은 `|dx|`와 `|dy|` 중 큰 쪽이며, 큰 쪽이 작은 쪽의 1.5배 미만이면 대각선 모호 입력으로 무시한다.
- 멀티 터치(손가락 2개 이상)는 무시한다. `touchcancel` 시 시작 좌표를 폐기한다.

### 스크롤 충돌 방지
- 보드 요소에 CSS `touch-action: none`을 적용해 보드 위 제스처가 페이지 스크롤/당겨서 새로고침/확대로 해석되지 않게 한다. 이 방식이면 `touchmove`에서 `preventDefault`가 필요 없고 passive 경고도 피한다.
- 보드 바깥 영역은 정상 스크롤 가능해야 한다. 페이지 전체의 `overscroll-behavior`는 건드리지 않는다.
- 보드에 `user-select: none` 적용.

## 7. 접근성

- 키보드만으로 모든 기능 사용 가능: 방향키 이동, Tab으로 "새 게임" 및 오버레이 버튼 이동, Enter/Space 활성화. 포커스 표시(`:focus-visible` outline)를 유지한다.
- 시맨틱 구조: `header`, `main`, 제목 `h1`("2048"), 점수 영역.
- 보드 컨테이너: `role="grid"` 대신 단순하게 `role="img"` 또는 `aria-label="게임 보드"` 를 두되, 현재 상태를 전달하는 `aria-label`을 갱신하지 않는다(과도한 낭독 방지). 대신 아래 live region으로 안내한다.
- 점수 안내: 시각적으로 숨긴 `aria-live="polite"` 영역(`role="status"`)에 이동마다 "점수 {n}점" 으로 갱신하되, 병합이 있어 점수가 변한 경우에만 갱신한다. 최고 점수 갱신 시 "최고 점수 갱신" 추가.
- 게임 상태 안내: 게임 오버 시 "게임 오버. 최종 점수 {n}점", 2048 달성 시 "2048 타일을 만들었습니다" 를 `aria-live="assertive"` 또는 같은 status 영역으로 알린다.
- 점수 박스는 `aria-label`로 "현재 점수", "최고 점수" 를 명확히 한다.
- 오버레이는 `role="dialog"` 가 아닌 `role="alertdialog"` 도 가능하나, 구현 단순화를 위해 `role="status"` + 버튼 포커스 이동으로 한다. 오버레이 닫힘 시 포커스를 "새 게임" 버튼 또는 보드로 돌려준다.
- 타일에는 `aria-hidden="true"`를 주어 개별 타일 낭독을 막는다(상태 전달은 live region 담당).
- `prefers-reduced-motion` 준수(5절).
- 색 대비 WCAG AA(텍스트 4.5:1) 유지, 터치 타깃(버튼) 최소 44x44px.

## 8. 엣지 케이스

- **연속 빠른 입력**: 이동 로직(`move`)은 동기 함수이며 상태는 즉시 확정한다. 애니메이션은 순수 시각 효과라 입력을 큐잉하거나 차단하지 않는다. 구현자는 매 입력마다 현재 상태에서 바로 `move`를 호출하고, 렌더는 `requestAnimationFrame`으로 합쳐서 한 프레임당 한 번만 DOM을 갱신한다. 타일 요소는 id 기준으로 재사용(키드 렌더링)하여 전환이 끊기지 않게 한다. 애니메이션 완료를 기다려 입력을 버리는 방식은 금지한다.
- **보드가 가득 찼지만 합칠 수 있는 경우**: 게임 오버로 판정하지 않는다. `canMove`는 빈 칸 외에 인접 동일 값도 검사한다. 또한 보드가 가득 찬 상태에서 움직일 수 없는 방향 입력은 `moved === false`라 무시된다.
- **마지막 병합으로 보드가 가득 차고 더는 못 움직이는 경우**: 이동 -> 병합 -> 새 타일 생성 -> `canMove` 검사 순서이므로, 새 타일로 보드가 가득 찬 직후 이동 불가면 즉시 게임 오버.
- **2048 이후 계속 플레이**: 2048 달성 시 오버레이를 보여 주고 "계속하기"를 누르면 `keepPlaying = true`로 오버레이를 닫아 계속 진행한다(이후 2048 달성 알림은 다시 띄우지 않음). 4096 이상도 계속 병합되며 점수는 동일 규칙. 새 게임으로 `won`, `keepPlaying`이 초기화된다. 2048 달성과 동시에 더 이상 못 움직이는 경우 게임 오버가 우선한다.
- **최고 점수**: 게임 오버·새 게임·페이지 이탈 이전에 이미 매 병합 시 저장되므로 별도 처리 불필요. 다른 탭에서 갱신된 값은 `storage` 이벤트로 반영(선택).
- **새 게임 버튼 오조작**: 진행 중 점수가 0보다 클 때도 확인 대화상자 없이 즉시 시작한다(단순함 우선). 이는 열린 질문 참조.
- **난수 부족 케이스**: 빈 칸이 0이면 타일 생성을 시도하지 않는다.
- **창 크기 변경/회전**: 타일 위치는 비율 기반 CSS이므로 JS 재계산 없이 대응된다.
- **포커스 이탈**: 다른 탭에 있다 돌아와도 상태는 변하지 않는다.

## 9. 검증 체크리스트 (review 단계)

기능
- [ ] 시작 시 타일 2개(값 2 또는 4), 점수 0
- [ ] `slideLine` 검증 예시 5개 모두 일치
- [ ] 한 이동에서 한 타일은 한 번만 합쳐짐 (`[4,2,2,0]` 등)
- [ ] 병합 점수가 합쳐진 값만큼 증가, 이동만 하면 점수 불변
- [ ] 이동이 없는 입력은 새 타일 생성·점수 변화 없음
- [ ] 새 타일은 빈 칸에만 생기고 대략 90% 2, 10% 4
- [ ] 4방향 모두 정상(좌우 대칭, 상하 전치 올바름)
- [ ] 가득 찼지만 합칠 수 있으면 게임 오버 아님, 합칠 수 없으면 게임 오버
- [ ] 2048 달성 오버레이, "계속하기" 후 진행, 이후 재알림 없음
- [ ] 새 게임: 점수·상태 초기화, 최고 점수 유지
- [ ] 최고 점수가 새로고침 후에도 유지
- [ ] localStorage 접근 차단 환경에서 오류 없이 동작(콘솔 에러 없음)

입력
- [ ] 방향키 사용 시 페이지가 스크롤되지 않음
- [ ] 수정키 조합(Cmd+←/→ 브라우저 뒤로가기 등)은 가로채지 않음
- [ ] 모바일에서 보드 위 스와이프가 4방향으로 동작하고 페이지가 스크롤/새로고침되지 않음
- [ ] 임계값 미만의 짧은 터치와 대각선 모호 제스처는 무시
- [ ] 키를 빠르게 연타해도 상태가 깨지지 않고 타일이 중복/누락되지 않음
- [ ] 오버레이 표시 중에는 이동 입력이 무시됨

UI / 접근성
- [ ] 라이트/다크 양쪽에서 모든 타일 값(2~2048, 4096+)의 텍스트 대비 4.5:1 이상
- [ ] 360px 및 375px 폭에서 가로 스크롤 없음, 점수판·보드·버튼 모두 보임
- [ ] 4자리 숫자가 타일 밖으로 넘치지 않음
- [ ] `prefers-reduced-motion` 시 애니메이션 없음
- [ ] 키보드만으로 새 게임/오버레이 버튼 조작 가능, 포커스 표시 보임
- [ ] 점수 변화가 live region으로 안내됨, 타일이 개별 낭독되지 않음
- [ ] 새로고침 시 테마 깜빡임(FOUC) 없음

규칙 준수

- [ ] 색상 하드코딩 없이 CSS 변수만 사용
- [ ] 인라인 이벤트 핸들러(`onclick=` 등) 없음, `var` 미사용, 세미콜론 사용
- [ ] `game.js`에 DOM 접근 없음

## 10. 결정 사항 (사용자 확정: 2026-10-06)
