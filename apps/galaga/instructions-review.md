# review 서브에이전트 지침: 갤러그 게임

## 역할
build 단계에서 만든 갤러그를 검증하고 `review.md`를 작성한다. build를 한 에이전트와는 별개의 시각으로, 코드를 직접 읽고 실제로 실행해 확인한다. 보고서의 "확인했다"는 실제로 실행·관찰한 것만 쓴다. 확인하지 못한 항목은 "미검증"으로 분리해 적는다.

## 수정 허용 범위
- 생성: `/Users/cky/dev/my-blog/apps/galaga/review.md`
- 수정 가능(문제 발견 시 최소 수정): `/Users/cky/dev/my-blog/apps/galaga/` 안의 `index.html`, `style.css`, `game.js`, `ui.js`
- 그 외 모든 파일은 읽기만 한다. 블로그 파일(루트 `index.html`, `post.html`, `css/`, `js/`, `posts/`, `CLAUDE.md`, `.claude/`)과 `spec.md`는 수정 금지. git 명령은 실행하지 않는다.
- 수정이 권한 등으로 막히면 우회하지 말고, 막힌 사실과 필요한 수정 내용을 review.md와 보고에 적는다.

## 검증 기준
`spec.md` 9번 검증 체크리스트 전체 + 아래 항목.
- 목숨: 시작 5개, 재시작 후 5개 복구, 5번 피격에 게임 오버, 추가 목숨 없음, 코드에 5가 직접 박혀 있지 않음.
- 순수 로직: `game.js`를 Node에서 불러 시뮬레이션(피격, 무적, 보스 2회 피격, 스테이지 전환, 동시 충돌, 터널링).
- 브라우저: `http://localhost:8000/apps/galaga/` (서버는 이미 실행 중, 새로 띄우지 않는다). 헤드리스 Chrome 등으로 가능한 만큼 실제 실행·스크린샷으로 확인. rAF 루프가 진행되지 않으면 다른 방법(예: 시간 주입, 스크립트 평가)으로 실제 플레이 상태까지 도달해 본다.
- 코드 점검: 전역 오염, 이벤트 리스너 누수, preventDefault 범위(iframe 스크롤 방해), localStorage·AudioContext 실패 처리, 색상이 CSS 변수에서만 정의되는지, 외부 의존 없음.

## review.md 구성
1. 총평(통과 / 조건부 통과 / 불통과)
2. 체크리스트 결과표(항목, 결과, 근거)
3. 발견한 문제와 조치(수정했다면 무엇을 어떻게)
4. 미검증 항목

## 완료 보고
총평, 수정한 내용, 미검증 항목을 5줄 이내로 보고한다.
