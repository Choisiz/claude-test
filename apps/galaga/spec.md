# 갤러그 게임 계획서 (spec)

## 1. 개요

하단의 자기 기체를 좌우로 움직이며 위에서 편대를 이루어 내려오는 적을 격추하는 갤러그 스타일 슈팅 게임이다. 적은 편대 상태로 좌우 이동하며 내려오다가 일부가 개별 급강하 공격을 하고 탄환을 쏜다. 기본 목숨은 5개이고, 적을 전멸시키면 난이도가 오른 다음 스테이지로 넘어간다. 점수판(현재 점수, 최고 점수, 남은 목숨, 스테이지)을 포함한다. html/js/css만 사용하고(프레임워크 금지, 외부 라이브러리 없음), canvas로 그리며 키보드와 터치를 모두 지원한다. 모든 파일은 `/apps/galaga/` 안에서 자체 완결된다.

## 2. 기능 목록

### 필수
- 좌우 이동 + 발사. 연사 제한: 발사 간격 최소 350ms, 화면 내 자기 탄환 최대 3발.
- 적 편대 등장(상단에서 진입 후 격자 배치), 편대 좌우 이동(벽에 닿으면 반전 후 한 칸 하강), 개별 급강하 공격.
- 적 탄환, 충돌 판정(자기 탄환-적, 적 탄환-자기 기체, 급강하 적-자기 기체).
- 목숨 5개. 상수 하나(`INITIAL_LIVES = 5`)로 정의하고 다른 곳에서 숫자를 직접 쓰지 않는다.
- 피격 시 무적 시간 2000ms (기체 깜빡임). 무적 중 피격 판정 없음.
- 스테이지 진행: 적 전멸 시 다음 스테이지, 난이도 상승.
- 게임 오버(목숨 0), 시작/일시정지/재시작.
- 점수판: 현재 점수, 최고 점수, 남은 목숨, 스테이지 (HUD, DOM 요소로 표시).
- 최고 점수 저장(localStorage). 접근 실패(예외, 비활성) 시 try/catch로 감싸고 메모리 값으로만 동작한다.

### 모바일
- 터치 조작: 화면 하단 좌/우 이동 버튼 + 발사 버튼(또는 캔버스 드래그 이동 + 자동 발사 옵션은 제외, 버튼 방식 단일화).
- 작은 화면 대응: 세로 모드 기준 레이아웃, 캔버스는 컨테이너 폭에 맞춰 스케일.

### 효과음 (사용자 확정: 포함)
- WebAudio로 합성한 짧은 비프음(발사, 적 격추, 피격, 스테이지 시작, 게임 오버). 오디오 파일 없음.
- AudioContext는 사용자의 첫 입력(시작 버튼) 이후에 생성한다. HUD에 소리 켜기/끄기 토글 버튼을 두고 상태는 localStorage(`galaga:sound`)에 저장한다(접근 실패 시 메모리). 기본값은 켜짐.
- 오디오 생성 실패 시 소리 없이 정상 동작한다.

### 선택 (시간 여유가 있을 때만)
- 폭발 파티클 효과.
- 별 배경 스크롤 (움직임 줄이기 설정 시 정지).

## 3. 게임 규칙 정의

### 목숨과 피격
- 시작 목숨 5. HUD에 남은 목숨 수를 숫자+아이콘으로 표시.
- 피격 시 목숨 1 감소, 기체를 중앙 하단으로 리스폰, 무적 2000ms. 이때 화면의 적 탄환은 제거한다(즉시 연속 피격 방지).
- 목숨 0이 되면 게임 오버.

### 추가 목숨
- 없음. 목숨은 5개 고정이며 점수로 늘어나지 않는다. (사용자 확정)

### 적 종류와 점수

| 종류 | 체력 | 편대 점수 | 급강하 중 점수 | 비고 |
|---|---|---|---|---|
| 벌레(Bee, 하단 2줄) | 1 | 50 | 100 | 기본 적 |
| 나비(Butterfly, 중간 2줄) | 1 | 80 | 160 | |
| 보스(Boss, 상단 1줄) | 2 | 150 | 300 | 1회 피격 시 색 변경, 2회째 파괴 |

### 편대
- 초기 배치(스테이지 1): 5줄 x 8열 = 40기 중 보스 1줄(8), 나비 2줄(16), 벌레 2줄(16) -> 총 40기. 모바일 좁은 화면에서도 같은 격자를 쓰고 스프라이트 크기만 스케일로 조정.
- 논리 해상도 기준 셀 크기 36x30, 편대 가로 이동 속도 40 px/s(스테이지당 +4, 최대 100).
- 벽에 닿으면 이동 방향 반전 + 24px 하강. 적이 자기 기체 라인(y=520)에 닿으면 즉시 목숨 1 감소 후 해당 적 제거(게임 오버 직행은 하지 않음).

### 급강하 규칙
- 일정 간격(스테이지 1: 2.0초)마다 편대에서 무작위 1기가 급강하를 시작한다. 보스는 스테이지 3부터 나비 1기를 호위로 함께 강하.
- 경로: 사인 곡선으로 좌우로 흔들며 하강(속도 150 px/s). 자기 기체 y 이하로 벗어나면 화면 위쪽에서 다시 나타나 편대의 원래 자리로 복귀.
- 동시에 급강하 가능한 최대 수: 스테이지 1은 2기, 스테이지당 +1, 최대 5.
- 급강하 중 자기 기체와 충돌하면 피격(적도 파괴).

### 적 탄환
- 편대 중 무작위 적이 발사(스테이지 1: 평균 1.5초에 1발, 동시 탄환 최대 3발). 탄환 속도 200 px/s. 급강하 중인 적은 하강 중 1회 발사 가능.
- 스테이지가 오르면 간격 감소(최소 0.5초), 속도 증가(최대 320 px/s), 동시 최대 탄환 수 증가(최대 8).

### 스테이지별 난이도 변화
| 항목 | 스테이지 1 | 증가량 | 상한 |
|---|---|---|---|
| 편대 이동 속도 | 40 px/s | +4 | 100 |
| 급강하 주기 | 2.0 s | -0.15 s | 0.7 s |
| 동시 급강하 수 | 2 | +1 (2스테이지마다) | 5 |
| 적 탄환 간격 | 1.5 s | -0.1 s | 0.5 s |
| 적 탄환 속도 | 200 px/s | +15 | 320 |
- 스테이지 클리어 시 보너스 점수: 1000 x 스테이지 번호 (목숨을 잃지 않았으면 추가 +500). 전환 시 "STAGE N" 안내 1.5초 표시.

### 자기 기체
- 이동 속도 240 px/s, 탄환 속도 480 px/s. 탄환 이동 시 화면 상단 이탈하면 제거.

## 4. 파일 구조

```
/apps/galaga/
  index.html   마크업(HUD, canvas, 터치 버튼, 오버레이 시작/일시정지/게임오버), 스크립트 로드
  style.css    색상 변수(:root, 라이트/다크), 레이아웃, 반응형, 터치 버튼, 오버레이
  game.js      순수 로직(DOM/canvas 의존 없음): 상수, 상태, update(dt, input), 충돌, 편대/급강하/발사, 점수, 스테이지
  ui.js        canvas 렌더, 입력(키보드/터치), 게임 루프, HUD 갱신, localStorage, 가시성 처리
  spec.md / instructions-*.md / review.md  (문서)
```
- `game.js`는 `window.GalagaGame`(또는 전역 네임스페이스) 하나로 노출하고, 난수는 주입 가능(`rng` 파라미터)해 테스트가 쉽게 한다.
- 이미지 파일은 사용하지 않는다(스프라이트는 코드로 그림).

## 5. 렌더링 설계

- canvas 사용. 논리 해상도 480 x 640(3:4 세로). CSS로 컨테이너 폭에 맞춰 비율 유지 스케일(`max-width` + `aspect-ratio`), 높이가 화면보다 크면 `max-height`로 제한 후 비율 유지.
- devicePixelRatio 대응: 캔버스 실제 크기 = 표시 크기 x dpr(상한 2), `ctx.setTransform(scale*dpr, ...)`로 논리 좌표를 그대로 사용. `ResizeObserver`/resize 시 재계산.
- 루프: requestAnimationFrame + 고정 시간 간격(1/60초 accumulator). 한 프레임 최대 누적 100ms(delta 상한). 렌더는 매 프레임, 업데이트는 고정 스텝.
- 스프라이트: 사각형/다각형 패스로 코드에서 직접 그림(기체: 삼각형 + 날개, 벌레/나비/보스: 픽셀 도트풍 도형). 외부 이미지 없음.
- 라이트/다크: 우주 배경이므로 캔버스는 어두운 팔레트 기본. CSS 변수(`--bg`, `--text`, `--accent` 등)를 `prefers-color-scheme`로 정의하고, canvas 색상은 JS가 `getComputedStyle`로 변수를 읽어 사용(색상은 CSS 상단 변수에서만 정의, 2048 앱과 동일 원칙). 라이트 모드에서도 캔버스 영역은 가독성이 유지되도록 별도 `--canvas-bg`, `--sprite-*` 변수를 둔다.
- 폰트: 시스템 폰트(2048 앱의 `--font-sans`와 동일).

## 6. 입력 처리

- 키보드: ←/→ 또는 A/D 이동, 스페이스 발사(누르고 있으면 연사 제한 간격으로 자동 발사), P 또는 Esc 일시정지, Enter 시작/재시작.
- 키 상태는 keydown/keyup으로 Set에 관리(동시 입력, 반대 방향 동시 입력 시 정지).
- `preventDefault`: 방향키·스페이스는 게임 포커스 중(게임 컨테이너가 활성 또는 플레이 중)일 때만 막는다. 입력 필드는 없지만 버튼 포커스 시 스페이스가 클릭으로 처리되지 않도록 처리.
- 터치: 화면 하단 컨트롤 영역에 ◀ ▶ 이동 버튼과 발사 버튼. `pointerdown/up/cancel/leave` 사용, 멀티터치 동시 입력(이동+발사) 지원. 버튼 및 canvas에 `touch-action: none`, `user-select: none`, 컨텍스트 메뉴 방지.
- 시작 시 시작 오버레이 버튼(클릭/탭/Enter)으로 시작. 자동 시작 없음.

## 7. 접근성

- 키보드만으로 시작/조작/일시정지/재시작 가능. 포커스 링 유지.
- 점수, 목숨, 스테이지는 DOM HUD 요소에 표시하고, 상태 변화 안내용 `aria-live="polite"` 영역(예: "목숨 4개 남음", "스테이지 2 시작", "게임 오버, 점수 1200")을 둔다. 점수는 매 점수마다 읽지 않고 스테이지 전환/게임 오버 때만 안내.
- 캔버스에는 `role="img"`와 `aria-label`로 게임 설명, 컨트롤 안내는 텍스트로 제공.
- `prefers-reduced-motion: reduce` 시: 별 배경 스크롤, 화면 흔들림, 파티클, 깜빡임(무적 표시는 투명도 고정 처리)을 줄이거나 끈다.
- 색상만으로 정보 전달하지 않음(보스 피격 상태는 색+모양 변화). 대비 4.5:1 이상 유지.

## 8. 엣지 케이스

- 탭 비활성화(`visibilitychange` hidden) / 창 blur: 자동 일시정지. 복귀 시 자동 재개하지 않고 일시정지 오버레이 표시. 복귀 시 시간 점프 방지를 위해 마지막 프레임 시각 리셋.
- 창 크기/방향 변경: 캔버스 재스케일, 게임 상태는 논리 좌표라 영향 없음.
- 프레임 드랍: 프레임 delta를 100ms로 상한, 고정 스텝 최대 6회/프레임.
- iframe 미리보기(블로그 카드): iframe 안에서는 자동 재생하지 않는다. 시작 오버레이("시작" 버튼)만 보이고 사용자 입력 전까지 루프를 돌리지 않는다. 쿼리 `?preview=1`이면 정지된 데모 화면(정적 편대)을 한 번만 그리는 모드를 지원해도 된다(선택). iframe 포커스 전에는 방향키/스페이스 preventDefault를 하지 않아 부모 페이지 스크롤을 방해하지 않는다.
- 동시 충돌: 한 스텝에서 한 번만 피격 처리(목숨은 1만 감소). 한 탄환은 한 적만 맞히고 소멸. 같은 프레임에 두 탄환이 같은 적을 맞힐 때 점수는 한 번만 부여. 무적 중 충돌은 무시. 피격과 스테이지 클리어가 같은 프레임이면 피격 처리 후 클리어 판정.
- localStorage 접근 실패: 최고 점수를 메모리로만 유지, 오류 무시.
- 게임 오버 직후 키 입력 연타로 즉시 재시작되는 것 방지(500ms 입력 잠금).
- 일시정지 중에는 입력 상태/타이머 모두 정지. 재개 시 눌린 키 상태 초기화.

## 9. 검증 체크리스트 (review 단계)

기능
- [ ] 시작 시 목숨이 정확히 5개이고 HUD에 5로 표시된다. 코드에서 `INITIAL_LIVES = 5` 상수 하나로 정의되고 재시작 후에도 5로 복구된다.
- [ ] 피격 시 목숨이 1씩 줄고, 5번 피격 후 게임 오버가 된다(4번째까지는 계속 진행).
- [ ] 피격 후 2초간 무적이며 이 동안 추가 피격이 없다.
- [ ] 좌우 이동이 화면 경계에서 멈춘다. 발사 연사 제한(350ms, 최대 3발)이 동작한다.
- [ ] 편대 이동/하강, 급강하, 적 탄환이 동작하고 충돌 판정이 올바르다.
- [ ] 보스는 2회 피격에 파괴된다. 점수표대로 점수가 오른다(편대/급강하 구분).
- [ ] 전멸 시 다음 스테이지로 넘어가고 난이도 값이 표에 따라 바뀐다. 스테이지 보너스가 적용된다.
- [ ] 점수가 아무리 올라도 목숨이 늘지 않는다(추가 목숨 없음).
- [ ] 효과음이 나고, 토글로 끌 수 있으며, 상태가 유지된다. 오디오 실패 시에도 오류가 없다.
- [ ] 점수판 4개 항목(점수, 최고 점수, 목숨, 스테이지)이 갱신된다.
- [ ] 시작/일시정지/재개/재시작이 키보드와 터치 모두에서 동작한다.
- [ ] 최고 점수가 새로고침 후에도 유지된다. localStorage가 막힌 상태(시크릿/예외)에서도 오류 없이 동작한다.

입력/모바일
- [ ] 키보드(←→/AD, 스페이스, P/Esc, Enter)가 동작하고 게임 중 페이지가 스크롤되지 않는다.
- [ ] 터치 버튼(이동+발사 동시 입력)이 동작하고 더블탭 확대, 길게 눌러 메뉴, 스크롤이 발생하지 않는다.
- [ ] 360px 폭 세로 화면에서 가로 스크롤 없이 모든 요소가 보인다.

렌더링/접근성
- [ ] 고DPI 화면에서 선명하고, 창 크기 변경 시 비율이 유지된다.
- [ ] 라이트/다크 모드 모두 가독성이 좋다. 색상이 CSS 변수에서만 정의된다.
- [ ] aria-live 안내가 동작한다. `prefers-reduced-motion`이 반영된다.

엣지
- [ ] 탭 전환 시 자동 일시정지되고 복귀 시 시간 점프가 없다.
- [ ] 프레임 드랍(백그라운드 후 복귀, 느린 기기)에서 적/탄환이 터널링하지 않는다.
- [ ] iframe 안에서 자동 재생되지 않고, 부모 페이지 스크롤을 방해하지 않는다.
- [ ] 동시 충돌 시 목숨이 한 번만 줄고 점수가 중복 가산되지 않는다.
- [ ] 콘솔 오류가 없고, 외부 라이브러리/이미지 의존이 없으며, 블로그의 다른 파일이 수정되지 않았다.

## 10. 확정된 결정 (사용자 승인)

1. 추가 목숨: 없음. 5개 고정.
2. 효과음: 삽입한다(WebAudio 합성, 토글 제공).
3. 터치 조작: 버튼 방식(◀ ▶ + 발사)으로 확정.
4. 블로그 카드 미리보기: 정지된 iframe(시작 오버레이 상태)으로 충분.
