# 갤러그 review

검증일: 2026-10-06 / 검증 방법: 코드 직접 읽기, Node 시뮬레이션(`game.js` require), 헤드리스 Chrome 154(CDP로 실제 키·터치 이벤트 주입, 스크린샷), `http://localhost:8000/apps/galaga/`.
build 쪽 자체 점검 결과는 참고하지 않았다. 아래 "확인"은 모두 직접 실행·관찰한 것이다.

## 1. 총평: 조건부 통과

핵심 로직(목숨 5, 무적, 보스, 스테이지, 동시 충돌, 터널링)과 브라우저 동작은 모두 정상이다. 검증 중 결함 2건을 발견해 최소 수정했고, 수정 후 재검증했다. 미검증 항목(실기기 터치, 실제 소리 출력, 시각 전환 탭)이 남아 있어 "통과"가 아닌 "조건부 통과"로 한다.

## 3. 발견한 문제와 조치

### 문제 1 (중간, 수정함): 스페이스를 누른 채 사망/일시정지하면 곧바로 재시작/재개됨
- 현상: 연사 중(스페이스 누름) 게임 오버가 되면 `syncOverlay(true)`가 "다시 시작" 버튼에 포커스를 준다. 스페이스를 계속 누르다(500ms 입력 잠금이 지난 뒤) 떼면 버튼 클릭이 발생해 즉시 재시작됐다(재현: 자동반복 keyDown 1초 후 keyUp, lives 0 -> 5). 같은 경로로 P로 일시정지 후 스페이스를 떼면 즉시 재개된다.
- 수정(`ui.js`): 스페이스를 누른 시점의 `document.activeElement`를 기록하고, 뗄 때 포커스가 그와 다른 버튼이면 `preventDefault`로 클릭을 취소한다.
- 재검증: 같은 시나리오에서 lives=0, gameover 유지. 새로 누른 스페이스로 시작·재시작 버튼을 누르면 정상 동작(회귀 없음).

### 문제 2 (낮음, 수정함): 호위 급강하가 동시 급강하 상한을 초과
- 현상: 스테이지 3 이상에서 보스가 급강하하면 호위 나비가 상한 확인 없이 추가돼, 스테이지 5에서 동시 5기(상한 4). 스테이지 9 이상이면 spec 상한 5를 넘어 6기가 될 수 있었다.
- 수정(`game.js`): 호위는 `divers + 1 < d.maxDivers`일 때만 함께 강하.
- 재검증: 스테이지 5 20초 시뮬레이션에서 최대 4기(상한 4).

### 참고(수정 안 함, 경미)
- iframe 높이가 낮거나(예: 560px) 가로 모드에서는 `--reserved: 17rem` 때문에 캔버스가 최소폭 240px까지 줄어 작게 보인다. 동작에는 문제 없고 카드 미리보기 용도에서는 시작 오버레이만 보이므로 허용 범위로 판단.
- `index.html`의 "목숨은 5개입니다" 정적 문구는 상수와 이중 정의다. 실행 시 `ui.js`가 덮어쓰므로 표시상 문제는 없다.
- 최고 점수는 일시정지·게임 오버·`pagehide` 때 저장된다(플레이 도중 브라우저 강제 종료 시 직전 저장 값 유지).

## 4. 미검증 항목

- 실제 모바일 기기/실제 터치 입력: CDP 터치 에뮬레이션으로만 확인. 더블탭 확대, 길게 눌러 메뉴, iOS Safari 동작은 확인하지 못했다.
- 실제 소리 출력과 `galaga:sound` 새로고침 후 유지: 헤드리스 환경이라 소리를 들을 수 없고, 프로그램 클릭에서는 AudioContext가 자동재생 정책으로 막혔다(실제 키 입력 경로에서는 경고 없음). 토글 UI와 오류 무발생만 확인했다.
- 실제 탭 전환(`visibilitychange`) 및 백그라운드 복귀: blur 이벤트 주입으로만 확인.
- reduced-motion, 다크 모드의 시각적 비교: 에뮬레이션 반영과 코드 분기만 확인했고 스크린샷 대조는 하지 않았다.
- 고DPI 실기기 선명도: dpr 2 에뮬레이션에서 캔버스 해상도 계산만 확인.
- 블로그 메인 `index.html`의 카드 삽입(embed 단계)은 이 review 범위 밖이라 보지 않았다.
- Safari/Firefox: Chrome 154 헤드리스만 사용.
