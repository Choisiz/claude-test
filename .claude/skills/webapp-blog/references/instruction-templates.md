# 서브에이전트 지침 파일 템플릿

`apps/{앱이름}/` 안에 `instructions-plan.md`, `instructions-build.md`, `instructions-review.md`로 저장한다. `{...}`를 채워 쓴다. 기준 실물은 `apps/2048/`, `apps/galaga/`의 같은 이름 파일이다.

서브에이전트 호출 프롬프트(한 줄이면 충분):
> `/Users/cky/dev/my-blog/apps/{앱}/instructions-{단계}.md`를 먼저 읽고 지침의 범위와 요구사항 그대로 수행하세요.

---

## instructions-plan.md

```markdown
# plan 서브에이전트 지침: {앱 이름}

## 역할
{앱} 웹앱의 **계획서만** 작성한다. 코드는 구현하지 않는다.

## 수정 허용 범위
- 생성/수정 가능: `/Users/cky/dev/my-blog/apps/{앱}/spec.md` (이 파일 하나뿐)
- 그 외 모든 파일은 읽기만 한다. 블로그 파일(`index.html`, `post.html`, `css/`, `js/`, `posts/`, `CLAUDE.md`, `.claude/`)은 수정 금지.
- 참고용으로 `/apps/2048/` 등 기존 앱을 읽어도 된다.

## 프로젝트 규칙 (CLAUDE.md 발췌)
- html, js, css만. 프레임워크 금지. 웹앱은 `/apps/{앱}/` 안에서 자체 완결.
- 외부 라이브러리 최소화(CDN 허용). 모바일 사용 가능. 블로그 색상 팔레트를 따른다. 사용법 안내 문구 필수.

## 사용자 요구사항
{요청 원문과 숫자·규칙}

## spec.md에 반드시 포함할 내용
1. 개요  2. 기능 목록(필수/선택, 모바일, 최고 점수 저장)  3. 게임·앱 규칙 정의
4. 파일 구조(index.html, style.css, game.js 순수 로직, ui.js)  5. UI/렌더링 설계(블로그 팔레트, 라이트/다크)
6. 입력 처리(키보드, 터치, 스크롤 충돌 방지)  7. 접근성  8. 엣지 케이스(iframe 미리보기 자동 재생 금지 포함)
9. 검증 체크리스트  10. 열린 질문(없으면 "없음")

## 작성 방식
한국어로, 구현자가 그대로 따를 수 있을 만큼 구체적으로. 수치는 초기값을 제시. 요구 범위를 지킨다.

## 완료 보고
핵심 결정과 열린 질문을 5줄 이내로 요약한다.
```

## instructions-build.md

```markdown
# build 서브에이전트 지침: {앱 이름}

## 역할
`/Users/cky/dev/my-blog/apps/{앱}/spec.md`(확정본)를 그대로 구현한다. spec.md를 먼저 끝까지 읽는다.

## 수정 허용 범위
- 생성/수정 가능: `apps/{앱}/` 안의 `index.html`, `style.css`, `game.js`, `ui.js` 네 파일만.
- 그 외 모든 파일은 읽기만 한다. spec.md, 블로그 파일, CLAUDE.md, `.claude/` 수정 금지. 블로그 메인 카드는 embed 단계에서 따로 한다.
- git 명령은 실행하지 않는다.

## 프로젝트 규칙
- html, js, css만. 외부 라이브러리·이미지·오디오 파일 없음. 자체 완결. 모바일 사용 가능.
- `/apps/2048/`의 테마 처리(FOUC 방지 스크립트, CSS 변수 구조, data-theme)를 따른다.
- 색상은 블로그 팔레트만, `style.css` 상단 변수에서만 정의한다.
- 사용법 안내 문구를 화면에 항상 보이게 넣는다.

## 핵심 요구 (반드시 지킬 것)
- {사용자가 못 박은 숫자·규칙. 예: 기본 목숨 5개, 상수 하나로 정의}
- game.js는 DOM/canvas 비의존 순수 로직, Node에서 로드·테스트 가능, 난수 주입 가능.
- iframe 안에서 사용자 입력 전 루프를 돌리지 않고, 포커스 전 preventDefault 금지.
- localStorage 키는 `{앱}:{항목}`.

## 완료 전 자체 점검
- `node --check`, game.js 핵심 로직 Node 시뮬레이션.
- 로컬 서버(`http://localhost:8000/apps/{앱}/`)는 이미 실행 중이다. 새로 띄우지 않는다.

## 완료 보고
만든 파일, 자체 점검 결과, spec과 달라진 점(없으면 "없음"), 직접 정한 사항을 5줄 이내로.
```

## instructions-review.md

```markdown
# review 서브에이전트 지침: {앱 이름}

## 역할
build 결과를 검증하고 `review.md`를 작성한다. 구현 쪽 자체 점검은 믿지 말고 직접 실행해 확인한다.
"확인했다"는 실제로 실행·관찰한 것만 쓴다. 못 한 것은 "미검증"으로 분리한다.

## 수정 허용 범위
- 생성: `apps/{앱}/review.md`
- 문제 발견 시 최소 수정: `apps/{앱}/`의 `index.html`, `style.css`, `game.js`, `ui.js`
- 그 외(spec.md, 블로그 파일, CLAUDE.md, `.claude/`)는 읽기만. git 명령 실행 금지.
- 수정이 권한에 막히면 우회하지 말고 막힌 사실과 필요한 수정 내용을 review.md와 보고에 적는다.

## 검증 기준
spec.md 검증 체크리스트 전체 + 아래.
- 순수 로직을 Node로 시뮬레이션.
- 브라우저 `http://localhost:8000/apps/{앱}/` (서버는 이미 실행 중). 헤드리스 Chrome 등으로 실제 실행·스크린샷.
- 코드 점검: 전역 오염, 리스너 누수, preventDefault 범위, localStorage 실패 처리, 색이 CSS 변수에서만 정의되는지, 블로그 팔레트 준수, 사용법 문구 존재, 외부 의존 없음.

## review.md 구성
1. 총평(통과 / 조건부 통과 / 불통과)  2. 체크리스트 결과표(항목, 결과, 근거)
3. 발견한 문제와 조치  4. 미검증 항목

## 완료 보고
총평, 수정한 내용, 미검증 항목을 5줄 이내로. 띄운 브라우저 프로세스가 남았으면 알린다.
```
